256 bits ÷ 32 bits = 8 lanes. A full SHA-256 hash still requires many instructions, so eight lanes does not mean eight complete hashes per instruction.

2. What are we calculating?

Each guess is a message such as gensys:100. The miner SHA-256-hashes the message, checks its target prefix, and repeats. Independent guesses are ideal for parallel processing.

Generate nonce guesses
Hash batches → reject misses → verify candidates

v0 (Python), v1 (C++) and v2 (Rust) all hash gensys:<unpadded decimal nonce>, so they search the same messages.

The patched tape-sha256 fast path specializes for short, single-block messages. A partial digest is only a filter, never a substitute for verifying a winner.

Measured November 2026 with a fresh state for each run; optimized six-thread range 90–105 MH/s. At 11 threads, mean ~109 MH/s. The custom AVX2 kernel is still available as --backend avx2; the optimized library is the default. A later paired run under heavier load (6 threads, 8 s, load 5.4–9.7) measured lower: optimized library median 87.6 vs custom AVX2 70.0 MH/s. The ranking held; the absolute numbers move with load. The 105 (six-thread) and ~110 (11-thread, single run 109.7) figures are single-run peaks, not typical. Approximate, not controlled isolated-hardware results; a controlled benchmark is not yet run.

5. Why not 8× faster?

Eight burners still need ingredients, pans, scheduling, and cleanup. SIMD improves parallel arithmetic, while the specialized algorithm removes wasted work. The combination is the speedup.
