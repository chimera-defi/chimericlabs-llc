Wren: a home-made Claude Duet

Anthropic's Claude Duet is a background agent that checks in each morning, does long jobs and asks before it sends or pays. It's waitlist-only for now. We had already built most of it ourselves, from Claude Code, a server and open tools. We call it Wren.

How it fits together

  • You ask from anywhere. Telegram (text or voice), the Claude app (Remote Control, voice chat), the desktop app or ChatGPT. All reach one server and memory, so several threads can run at once.
  • Opus plans and checks; cheaper models do the work. Codex builds, Haiku reads, other agents help over a bus.
  • Files keep the state. Checkpoints, notes and lessons live on disk.
  • You approve orders. A phone gate covers selected other actions.

How it grew

  • June 2026. Session tooling (crss) lets Claude Code run for days on a server and be reached from a phone.
  • August. A shared message bus lets Claude, Codex, ChatGPT and other agents hand each other work.
  • October. DispatchBench routes each job to the cheapest model. The orchestrator gets a persona, a memory and a name: Wren.
  • 26 October. A 07:00 Telegram brief, and a phone approve/deny gate, tested live both ways.

What it's made of

  • The server: a dedicated server, on 24/7, with root access.
    • Intel i7-8700: 6 cores, 12 threads.
    • 62 GB RAM.
    • 2.8 TB of fast SSD storage.
    • Three 1 TB drives striped together (RAID0), so no spare copy.
    • Ubuntu 24.04 Linux.
    • About 35 scheduled jobs: 25 system timers, 10 cron entries.
  • crss: starts, messages, hands off and repairs long-running sessions for every agent on the box.
  • token-reduce and QMD: read only the slice a task needs. QMD is a local search engine over our markdown.
  • DispatchBench and the delegate skills: the cheapest model that passes takes each step; new models plug in.
    • Opus plans and checks.
    • Codex builds and gives the final review.
    • Haiku does cheap reads and sweeps.
    • Devin takes browser and sandbox jobs.
    • If Codex is out: Haiku takes small builds, and Grok reviews.
    • Fable gave second opinions until we paused it on 28 October.
  • The bus: a small mailbox database where agents post tasks and replies, including Hermes and OpenClaw.
  • Phone bridges: the Hermes gateway and takopi for Telegram; Claude Remote Control for the app.
  • ChatGPT's apps, through Codex: brokers, market data, GitHub and site hosting.
  • Market data on the server: Databento and Yahoo Finance prices, FRED economic data, SEC EDGAR filings, and web search.
  • Daily jobs: alerts, a daily brief, and the approval gate.

We also run gbrain, a knowledge-base server. Its health check fails and a sync has aborted, so nothing depends on it.

If you copy this: add an off-box backup before anything else.

What others do

  • OpenClaw "dreaming": a nightly rewrite of the memory file, backed up first. It appends instead if it would drop over a quarter.
  • Hermes: pluggable memory providers, and a curator that retires unused skills.
  • ChatGPT: saved memories and references to past chats, in your OpenAI account, not in files you can diff.
  • Papers: MemGPT pages memory like an operating system. Reflexion writes lessons after failures.

Runs the work

  • DispatchBench measures fit, routing each step to the cheapest passing model.
  • Jobs run for weeks, resumed from checkpoints.
  • Sessions end with a recap and one-tap next steps.

Builds its own tools

  • We built, and can change, crss, token-reduce and DispatchBench.
  • It benchmarks itself: a largely unattended six-week Ethereum client run.
  • A persona and a lesson hook, borrowed openly from Hermes and OpenClaw.

What we learned

  • Expensive head, cheap hands. The strong model plans and checks.
  • A "done" is a claim. Wren re-runs the check before believing a helper.
  • Borrow openly, then add only what fixes a repeat failure. Hermes and OpenClaw gave us the persona, lesson hook and rules for what not to remember.
  • Remove scaffolding as models improve. Re-test each hook and rule per model; drop what stops paying.
  • Control the server, control the gates. You decide what needs your yes.

In short: one strong model on your server, reachable by phone, handing work to cheaper agents and asking before orders and selected actions go out.
