Trading bot 0x51C7…2A7F: who can move its money

This Ethereum contract is a trading bot that keeps its own money. Only accounts on its lists can move that money. We read its verified code and rebuilt it to check.

Eight short sections, about a minute each. Every section opens with its point.

What it does

It trades its own funds on Uniswap and Curve. It backs signed price quotes for traders. It pays out to an approved list.

Who it is for

Only the people who run it. It has no deposit function and no user balances. Outsiders have no reason to call it.

What to watch for

Tokens sent to it by mistake can't be pulled back by the sender. A call to a function it lacks succeeds and does nothing.

Verdict: a privately run trading and market-making bot. It is not a drainer, a contract built to steal approved tokens. It is not a honeypot, a trap that keeps deposits. No function lets an outsider take its money. No function pulls tokens from anyone else. Every path that moves value needs a role, a list entry or an allowance.

Its verified code calls itself an “MEV bot and contract wallet” (line 81). MEV is profit from choosing which trades go in a block, and in what order. Bots chase it by trading on price gaps between pools.

The eight sections

How it works

  1. Who writes the lists. A registry contract adds and removes every account.
  2. How one trade works. Five steps, from an operator's call to the builder tip.
  3. How a price quote is checked. An off-chain key signs quotes. The bot vouches for that key.
  4. Where the money can go. Five exits, each behind a list.
  5. The emergency brake. Any staff account can stop it. Only the multisig restarts it.

What to make of it

  1. What a reviewer would flag. Five design facts, not claims that anything went wrong.
  2. What we checked, and what we didn't. The code matches the chain. Some things stay unproven.
  3. How to read a contract yourself. Five steps on a block explorer, without signing anything.

Section 1 of 8

1. Who writes the lists

One outside contract, the registry, decides who is on every list.

The registry calls the bot to add or remove an account. Nothing else can change these lists (lines 240–349).

A Uniswap pool joins only if a factory lists it for its tokens. The registry names that factory each time (note 1). Curve pools join with no such check (lines 285–287).

The owner, the registry and the wrapped-ETH contract are fixed at deploy. The bot has no upgrade path. There is no proxy, delegatecall or selfdestruct.

Section 2 of 8

2. How one trade works

A trade runs only for an operator, on a listed pool, with the bot on.

Curve and Uniswap V2 trades follow the same gates (note 2). Many trade functions have a version that takes a deadline.

A tip goes only to a listed block builder. The bot does not check whether the tip arrived (note 3).

Section 3 of 8

3. How a price quote is checked

The bot acts as a market maker: an off-chain key signs its price quotes.

The question in the second path is a standard one, called EIP-1271. Only callers on the list may ask it.

Tokens then leave through allowances. Section 4 covers those.

4. Where the money can go

Money leaves the bot by five exits. Each one sits behind a list.

On 14 Nov 2026 the bot was on. It had 10 approved spenders. Among them were Uniswap's Permit2, the 1inch router and Bebop's settlement contract. It tracked 161 approved tokens. In all, 613 allowances were above zero.

Section 5 of 8

5. The emergency brake

Any staff account can stop the bot. Only the multisig can start it again.

Pool callbacks don't check the switch. A failed zeroing is only logged. The allowance stays open. The token still drops off the bot's list (lines 416–426).

On that day, stopping it would emit 614 logs. That fits in one block (note 5).

The stop function

Section 6 of 8

6. What a reviewer would flag

Five design facts stand out. None is a claim that anything has gone wrong.

  1. The registry holds the keys. It names the transferers and the recipients. Together those two lists can send out any token or ETH. The registry's own code is not verified on Sourcify or Blockscout. So its rules can't be read.
  2. The Curve payment trusts the transaction's sender. It pays any listed Curve pool that asks. The pool names the coin and the amount. An operator must have signed the transaction. It checks tx.origin, not whether the bot started the swap. Curve pools join with no factory check (lines 285–287).
  3. A failed revoke drops the token anyway. The token leaves the list first. Then its allowance is zeroed. A log is the only trace of a failure (lines 416–426).
  4. Some results are ignored. Nothing checks that these worked: ETH payouts (line 489), builder tips (686), pool payments (589, 656, 665, 669, 678).
  5. A stored timelock does nothing here. A one-day delay is set at deploy. It is only read back. This contract never enforces it. See lines 128, 176, 362.

Section 7 of 8

7. What we checked, and what we didn't

The verified code matches what runs on chain. Equivalence for every input is not proven.

Checked

  • Built with its exact compiler settings, the source gives the deployed code byte for byte. Deploy arguments match too.
  • We wrote a shorter, readable copy. It has the same 63 functions, argument types and storage layout.
  • Both ran one test that calls every external function. All 331 compared results matched.
  • We ran both on a local copy of mainnet at block 26,415,084. They gave the same swap output. Both zeroed the same 613 allowances.

Not checked

  • The metadata hash differs. The verified file is a rebuild with stand-in names (note 6).
  • Equivalence for every possible input. Tests are examples, not a proof.
  • The outside contracts: the registry, the multisig's signers, the venues and the spenders.
  • Who runs it. We make no claim about that.

Section 8 of 8

8. How to read a contract yourself

A block explorer shows any contract's code and state without signing anything.

  1. Open the address on Blockscout or Etherscan.

  2. Pick the Contract tab. A check mark means the source is verified. It was compiled and matched to the code on chain.

  3. Read the Code view. Search it for the function names you see.

  4. Open Read Contract to see its current state. Reading sends nothing.

  5. Leave Write Contract alone. It asks your wallet to sign a transaction.

Etherscan blocks automated link checks, so our explorer links go to Blockscout. The address is the same on both.

Words used on this page

Ethereum words

  • MEV. Profit from choosing which trades go in a block, and in what order. ethereum.org explains it.
  • Block builder. The party that packs transactions into a block. The bot reads its address from block.coinbase.
  • WETH. Wrapped ETH: ETH held as a token, so contracts can trade it like one.
  • Allowance. Permission one account gives another to pull a set amount of a token. Defined in ERC-20.

Contract words

  • Multisig. A wallet that needs several keys to sign. This one is a Safe.
  • RFQ. Request for quote: a trader asks a market maker for a signed price.
  • EIP-1271. A standard question a contract answers: did your key sign this?
  • tx.origin. The account that signed the whole transaction, not the direct caller.
